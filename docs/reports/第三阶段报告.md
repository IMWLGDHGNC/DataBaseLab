# 第三阶段报告  数据库编程与事务处理

第10至13周在第二阶段 v1.0 零食网店上整理 v2.0 评审版。数据库集中处理计价、盘点、订单完成和采购验收，窗口与递归查询提供销售和分类分析。本文实验结论已用 2026-11-28 Windows 新库复跑核对，组员可补写个人分工和人工实验结论。参见[第十三周讲解](../course/第十三周任务讲解.md)和[Windows 本轮证据](../../result/third-stage/windows-20261128/README.md)。

## 设计思路与程序对象

应用保留三类角色和单仓库存。顾客下单时创建预留并锁定可售库存，模拟支付后进入待出库。店员确认出库才扣减实物现存量。管理员审批单商品采购后，店员整单验收时建立采购批次。SQL 过程集中执行状态校验，应用角色通过受限授权调用；数据库同时保留原价、折扣、实付、采购来源、流水和审计。

## 高级查询

销售收入排名使用 `DENSE_RANK` 保留并列名次，不跳过后续名次。完成订单按完成时间和订单号稳定排序，分别计算累计收入与最近三笔均值，开头不足三笔按实际窗口计算。历史样例和补充模拟订单的查询结果与独立计算逐行比对。商品分类加可空父级外键，递归 CTE 从指定分类沿父子关系展开，返回后代编号、父级、相对层级和路径。测试覆盖根、中间、叶子、未知编号和间接环。参见[窗口查询](../../sql/week11/window_query.sql)、[递归查询](../../sql/week12/recursive_query.sql)、[递归结果](../../result/week12/README.md)。

## 业务事务与验证过程

- 订单完成由 `sp_CompleteOrder` 检查待出库状态、支付和预留，按商品及批次升序锁定并转出库。扣货受库存条件保护，后续写出库流水、状态及完成时间、会员积分。第12周模拟 P/Q 从 20/15 到 17/11，产生两笔出库和审计，并赠 27 分。测试在写入后注入 51920，逐表验明库存、订单、流水、审计与积分全部恢复。
- 采购验收由 `sp_ReceivePurchase` 确认批准明细、商品与数量，按商品主键获取锁，然后新增批次和流水并更新收货人、时间与单据状态。模拟 Q 从 11 到 18，批准数量仍为 7。写入批次和审计后注入 51921，回滚恢复 11，单据仍已批准。两项事务重复调用均拒绝且无二次写入。
- 独立调用由过程开启并关闭事务。应用或其他外层事务已存在时，过程用保存点并由外层最终提交。状态、库存、流水、触发器审计及积分都受同一提交边界保护。应用锁串行业务写入，库存键规约统一为先商品后批次。参见[第12周流程](../week12/README.md)、[第13周访问顺序](../week13/README.md#真实业务过程和回归)及[23项事务证据](../../result/week12/README.md)。

## 并发实验与结论

在两个 SQL Server 会话中，A 未提交时持有 P 的排他锁，B 对同一键等待。A 提交和回滚后 B 都能完成，终态分别为 P=13 和 P=15，对照单据状态即可解释是否保留那两件出库。真实订单与补货过程的相同两轮实测中，等待先出现在事务级应用锁上，采购增加的 5 件另记新批次。

未提交读看见 A 尚未提交的 15，A 回滚后恢复 10。已提交读在 RCSI 关闭时等待并返回 10，开启时直接读到已提交的 10。使用 `READCOMMITTEDLOCK` 时仍可看到锁等待。已提交读可在同一事务先后读到 10 和 15。可重复读把已读键的共享锁保留到提交，A 两次都读 10，随后 B 才能完成。未测试范围插入或幻读。

反序更新中 A 持 P 等 Q，B 持 Q 再等 P，SQL Server 给 B 返回 1205。清理后 B 的补货撤销，A 提交后 P/Q 为 8/6。改为都先 P 后 Q 时，B 在 P 上普通等待，A 提交后双方均完成，P/Q 为 13/11。统一访问顺序消除了本例循环。最后用真实 `sp_CompleteOrder` 竞争 10 件库存，两张订单各需 6 件，只有一张完成，库存余 4，失败单无完成时间或出库增量。参见[第13周操作](../week13/README.md)和[本轮锁资源与步骤](../../result/third-stage/windows-20261128/README.md#三会话观察)。

## 实验总结

Windows 新库按第10至13周顺序通过 87、76、23、14 项，另通过 103 项 Web 回归。订单和补货的失败回滚与重复调用保住了库存、流水和审计的一致性。复跑覆盖了两种 RCSI 设置下的已提交读、死锁及修正后的等待。参见[本轮通过标记](../../result/third-stage/windows-20261128/run-summary.txt)。

应用与两个数据库过程共用事务级排他应用锁，进入同一写事务时会串行执行，简化了库存检查与写入的协调。即使两次写入针对不同商品，第二次也可能在应用锁上等待，因此写事务耗时会限制并发吞吐。本轮观察了等待关系和业务结果，吞吐量尚未量测。

Web 将顾客登录绑定到 `CustomerID`，订单列表、详情和写操作按该身份限制，回归检查了跨顾客拒绝。应用数据库账户使用表级、列级及过程授权，直接连接数据库时受数据库授权范围约束。顾客本人订单的行级边界由 Web 服务执行。参见[应用身份与权限](../week7-9/README.md)和[Web 回归清单](../../result/third-stage/windows-20261128/web-checks.txt)。
