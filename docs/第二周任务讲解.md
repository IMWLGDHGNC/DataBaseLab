# 数据库实验课程 第二周任务讲解

## 1. 本周目标

第二周要把第一周确定的线上零食网店业务对象，转换为可以用关系数据库表达的关系模式。本周的重点不是写建表 SQL，而是把每张表的属性、域和码说清楚，并准备能够检验设计的样例元组。

本周完成后，应当能回答以下问题：

- 业务中哪些对象需要分别记录？
- 每张表需要哪些字段，每个字段表示什么？
- 字段允许什么样的值？
- 如何唯一识别一条记录？
- 表与表之间如何通过外码建立联系？
- 样例数据能否表达第一周约定的采购、库存、销售、支付和积分流程？

## 2. 与第一周的衔接

第一周已经确定了线上零食网店的范围、角色、业务流程和数据边界。第二周应沿用这些约定，不另起一套互相矛盾的业务规则。

特别需要保持一致的内容包括：

- 商品数量按最小销售单位记录，不把“10 箱×每箱 30 瓶”作为数量字段的存储值。
- 库存需要支持批次、生产日期、到期日期、现存量、锁定量和可售状态。
- 销售订单可以包含多种商品，历史成交单价需保留在订单明细中。
- 支付、库存出库和积分增加是相关但不同的业务记录。
- 第一阶段只实现积分累计，暂不实现积分兑换、退款、退货和拆单。
- 已被历史业务引用的商品、供应商、顾客和员工记录应当保留，通过状态字段表示停售或停用。

## 3. 核心概念

| 概念 | 在本项目中的含义 |
| --- | --- |
| 关系模式 | 一张表的逻辑定义，包括表名、字段和各种码 |
| 属性 | 表中的字段，例如商品名称、当前售价、订单状态 |
| 域 | 字段允许的值的集合，包括数据类型、长度、精度、空值、默认值和取值范围 |
| 主码 PK | 从候选码中选定、用来唯一识别记录的码 |
| 候选码 | 能够最小且唯一地识别记录的属性或属性组合；未被选为主码的候选码可标为 UNIQUE |
| 外码 FK | 引用另一张表的主码或候选码，用来表示两张表的关联 |
| 元组 | 表中的一行数据，例如一个商品或一张订单的一条实例 |

## 4. 任务拆解

### 任务一 确定进库的表

从第一周的数据对象中整理表清单。对每张表先写明用途，再决定表名。需要区分“一个独立业务对象”和“一个对象的属性”；不要因为每个名词都单独建表，也不要把多个不同的业务事件挤在一张表中。

本步产出：表名、业务用途、与其他表的大致关系。

### 任务二 定义属性和域

为每张表列出字段。每个字段至少记录：

1. 字段名；
2. 数据类型；
3. 长度或精度；
4. 是否允许为空；
5. 默认值；
6. 取值范围或枚举值；
7. 字段的业务含义。

定义域时要使存储值保持原子性。例如，数量字段存储 `300`，计量单位由商品数据解释；金额字段存储 `660.00`，不把“元”字存入数值字段；时间使用统一格式。

### 任务三 标注各种码

对每张表标出：

- 主码：`PK`；
- 其他候选码：`UNIQUE`；
- 外码：`FK -> 被引用表.被引用字段`。

标注外码时，不能只写“这是外码”，还要写清它引用哪张表的哪个字段。对可能唯一但不应作为主码的字段，说明它是否真的具备稳定、非空和唯一的业务条件。

### 任务四 编写样例元组

每张表编写 2–3 行符合线上零食网店场景的样例数据。样例应使用虚构的人员与联系方式，但数量、价格、时间和状态之间必须符合业务常识。

样例数据至少要检查：

- 所有外码值都能在被引用表中找到；
- 同一个主码或候选码不重复；
- 金额与“数量 × 单价”等计算结果一致；
- 原库存量、变动量和现库存量能对上；
- 创建、支付、出库和完成时间顺序合理；
- 数据符合第一周确定的业务边界。

### 任务五 做跨表一致性走查

选择一次采购入库和一次会员购买，沿外码从头到尾核对数据。走查时应能说明供应商、采购单、商品、库存批次、销售单、顾客、支付和积分记录如何相互对应。

## 5. 建议的文档格式

每张表可以先给出关系模式，再分别给出字段定义和样例元组。

### 关系模式示例

`Product(ProductID, Name, Brand, Specification, SaleUnit, CategoryID, CurrentPrice, SaleStatus, ReorderLevel)`

### 字段定义表模板

| 字段 | 数据类型 | 长度或精度 | 允许空 | 默认值 | 域或取值范围 | 码 | 含义 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | PK / UNIQUE / FK | 待填写 |

### 样例元组模板

| 字段一 | 字段二 | 字段三 |
| --- | --- | --- |
| 样例值 | 样例值 | 样例值 |
| 样例值 | 样例值 | 样例值 |

## 6. 本周应交付的内容

1. 表清单：列出所有进入数据库的业务对象及对应表。
2. 字段定义：对每个字段写明属性和域。
3. 码标注：标出每张表的主码、候选码和外码。
4. 样例元组：每张表 2–3 行符合实际业务的样例数据。

## 7. 完成自查

- [ ] 每个第一周确定为“进库”的核心对象都已处理。
- [ ] 每张表的用途和每个字段的业务含义都能解释。
- [ ] 每个字段都已定义类型、长度或精度、空值、默认值和取值范围。
- [ ] 每张表都已标注 PK，并检查 UNIQUE 候选码和 FK。
- [ ] 每个 FK 都写明了被引用表和字段。
- [ ] 每张表都有 2–3 行样例元组，且外码可找到对应记录。
- [ ] 金额、库存和时间在各表之间一致。
- [ ] 设计没有把退货、退款等第一周明确暂缓的功能误当为当前必做范围。
- [ ] 小组成员能解释字段、码和表间关系，并保留 AI 辅助与人工修改记录。

## 8. 与第三周的衔接

第三周将根据本周的关系模式编写建库和建表语句，并完成数据的增、删、改、查。因此，本周的表名、字段名、数据类型、码和样例数据需要统一，避免第三周编写 SQL 时再大量返工。
