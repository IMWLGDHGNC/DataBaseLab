# 线上零食网店数据库原型 v0.1 阶段报告（文字摘要）

本文件为 GitHub 公开文字版。课程提交包中的正式 PDF 含课程署名及远程账户截图，仅私下提交；此处提供不含个人身份信息的报告、设计和验证索引。

## 设计思路

项目把线上零食网店的采购、批次库存、销售订单、模拟支付和会员积分纳入数据库；退货、退款、真实支付和自动配送暂不纳入。业务边界与店长、采购员、库存管理员、订单管理员职责见 [Week1](Week1.md)。

关系模式由 15 张表构成。商品与类别分开，库存按采购来源建批次，订单明细保存成交时单价，库存锁定与现存量变动分别记账。主码采用稳定业务编号；商品组合候选码、类别名称与顾客账户等使用 UNIQUE；外码连接采购、批次、订单、支付、积分与经办人。完整字段、码和样例见 [Week2](Week2.md)。

## 实验过程

第三周使用 SQL Server 2022 LocalDB 实现建库、建表、46 行样例数据和商品、库存、订单 CRUD，并验证 12 项非法数据。第四周增加多表连接、已完成销售统计、库存状态查询、三个视图、异常解决说明约束和四个员工岗位的列级/视图级授权。后来又补充普通顾客与会员角色，通过受控过程限定为本人订单和积分查询，并修正订单详情视图的无明细订单处理。全流程由 [Run-Week4.ps1](../scripts/Run-Week4.ps1) 从空库执行；具体顺序和运行命令见 [Week4](Week4.md)。

第一次在本地 `DataBaseLab_Week4` 运行，第二次在独立新库运行。补强事务隔离和权限案例后，又在课程服务器独立临时库复验，并正式部署为服务器数据库 `DataBaseLab_Week4`；当时均为 15 表、46 行。完成销售额核对为 64.50 元、15 件；B01 在演示日期已到期，可售量为 0。新约束六例、原有 12 项非法数据测试和当时的权限 17 例均通过。2026-09-30，补充的顾客、会员权限及视图回归案例在课程服务器空库复现并升级正式库；34 项权限测试通过，15 张业务表的升级前后数据摘要一致。完整输出保存在 [result 目录](../result/README.md)。

## 实验总结

把“已支付”直接计为“已销售”会多算待出库订单；本阶段统计以“已完成”为口径。视图便于重复查询，但当前库存视图按当天判断是否到期，历史报表须指定明确的截至日期。CHECK、FK 和唯一性约束可直接拒绝多类非法写入；涉及多表金额、库存流水、角色审批人与业务岗位一致性等规则仍需要受控业务入口和事务。角色测试证明了当前授予范围内的允许与拒绝，不代表已经实现所有岗位的完整业务工作流。

## 设计演变与表清单

最初草稿把商品库存余额和交易记录放在较少的对象中。最终模式将采购单/明细、销售单/明细分开，以批次记录采购来源与保质期；用锁定记录与库存流水区分可售量和现存量。顾客统一存储普通顾客与会员身份，积分余额与积分流水分别记录。明细保存成交单价，避免商品调价改变历史订单金额。原始过程见[设计草稿](../原始表设计草稿.png)，最终字段、候选码、外码、样例与取舍见 [Week2](Week2.md)。
