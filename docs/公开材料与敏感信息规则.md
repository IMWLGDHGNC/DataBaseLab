# 公开材料与敏感信息规则

本规则适用于整个项目，包括所有分支的代码、样例数据、报告、AI 使用记录、运行日志、截图、图表、PDF、压缩包，以及提交作者信息、提交说明、GitHub PR、Issue、Release 和附件。署名报告和课程私下提交包仅通过课程指定的私密渠道交付。

## 允许公开的内容

- 课程要求、业务分析、数据库设计、SQL 和复现脚本。
- 明确为虚构的业务样例；现有种子数据保持其模拟性质，不替换为真实顾客或员工信息。
- 使用“成员 A/B”的实际分工、已脱敏的说明及运行证据。
- 通用环境变量、占位符、环回地址 `127.0.0.1` / `localhost` 和公共技术资料链接。

## 禁止公开的内容及替代方式

| 内容 | 公开材料的替代方式 |
| --- | --- |
| 真实姓名、学号、手机、私密邮箱、住址、收货资料 | 匿名成员编号或虚构样例；需要署名的原件只私下提交 |
| 个人账户名、设备名、聊天文件目录、用户目录 | 环境变量、相对路径或 `<用户>` 等占位符；Windows 路径使用 `$env:USERPROFILE` |
| 非公开服务器地址、域名、端口、SSH 账户和主机指纹 | `<服务器地址>`、`<SSH端口>`、`<SSH用户>` 等占位符，真实参数通过私密渠道获取 |
| 密码、令牌、Cookie、会话信息、连接串中的凭据、私钥、证书密钥、备份中的真实数据 | 环境变量或本地秘密文件；不把真实值作为示例、测试输入或黑名单提交 |
| 含上述内容的截图、报告、导出文件或压缩包 | 制作脱敏公开版本；无法可靠脱敏时仅保留本地原件，以安全文字或日志提供公开证据 |

上传作业、更新仓库或记录真实提示词的任务也必须遵守本规则。提示词含敏感信息时应脱敏并说明已脱敏。公开内容的脱敏不能改写实际实验结果、分工或审核结论。

## 本地保存与忽略配置

原始署名报告、私下提交包、未脱敏截图和连接配置优先保存在仓库外；需要放在工作目录时，使用 `private/`、`local-only/` 或 `output/`。这些目录及常见秘密文件、压缩包已列入根目录 `.gitignore`。

`.gitignore` 只减少误添加，不能移除已经跟踪的文件，也不能检查图片中的文字、PDF 隐藏层、压缩包成员或历史提交。不要用 `git add -f` 绕过这些目录和秘密文件的忽略规则。脱敏后需公开的材料放入普通公开目录，先完成下面的检查再添加。

## 每次提交与上传前检查

在仓库根目录运行：

```powershell
git status --short
git diff --cached --name-only
git diff --cached
git diff --cached --check
git var GIT_AUTHOR_IDENT
```

1. 核对暂存文件列表，确保没有署名原件、私下提交包、秘密文件或真实数据库备份；检查已跟踪文件，不只检查新增文件。
2. 阅读实际差异，核查个人身份、联系方式、个人路径、服务器参数和凭据。提交作者使用公开昵称与 GitHub noreply 邮箱，不使用学号或私密邮箱。
3. 打开图片、PDF、Office 文件并检查内容及元数据；检查截图窗口标题、终端提示符、地址栏和边栏。PDF 脱敏需移除底层文本、图像和附件，不能只盖一个色块。压缩包必须解包检查所有成员。
4. 用环境变量、占位符、匿名编号或模拟数据替换敏感内容；无法确认安全的文件留在本地。修复后重新暂存、检查链接和实际文件内容，保证复现与证据有效。
5. 检查提交说明、PR/Issue 正文、Release 和上传附件。确认当前提交及本次将推送的其他提交均无敏感内容后再上传。

本流程是必须执行的内容检查；`git diff --cached --check` 只检查空白问题，不是自动隐私扫描器。对未修改的已有材料也不得仅凭文件名或扩展名判定安全。

## 已上传或已提交的敏感信息

发现后立即停止继续传播，并告知仓库负责人文件位置和信息类型，不在公开讨论中复制真实值。凭据泄露时先撤销或轮换凭据，再清理材料；个人信息需要检查历史提交和已有附件。只修改最新文件不足以移除历史记录，共享历史重写或远端附件删除须由负责人确认后执行。
