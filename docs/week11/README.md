# 第11周 触发器与窗口函数

本周在[第10周数据库对象](../week10/README.md)之后增加库存审计与订单完成规则，完成销售排名、累计和移动平均。要求见[课程原文](../course/第11周任务讲解.md)。自动验证通过，学生逐项人工审核待确认；本周未部署课程服务器。

## 库存审计

[trigger.sql](../../sql/week11/trigger.sql)创建 `InventoryAudit` 辅助表和 `tr_InventoryAudit`。业务模型仍为15张表，审计表单独计数，不改写v1.0历史基线。触发器在 INSERT、UPDATE、DELETE 后使用 inserted/deleted 全连接逐批次写入，单次影响多行时每个变化批次都有记录。

记录包含批次、商品、前后现存量、变化数量、前后质量状态、操作类型、时间与操作员工。插入的旧数量和删除的新数量为NULL，计算变化时视为0；删除记录不受批次外键约束，从而保留历史。质量、有效期、批号等变化也会留下数量差0的记录；无行命中或所有属性均未改变时不写假变化。批次编号和采购来源禁止更新，变更来源须保留原历史另建合法批次。

操作员工来自连接的 `SESSION_CONTEXT('OperatorID')`。SQL盘点、出库过程临时设置并恢复该值；Web采购验收也设置员工。普通SQL未设置时记录 `ActorType=SQL / OperatorID=NULL`，不推断员工、不记录真实数据库登录名。连接上下文不随事务回滚自动恢复，直接SQL演示应显式清空；正式过程在成功与失败分支均恢复旧值。

审计和原修改属于同一事务，失败时审计行一同回滚。另拒绝现存量低于该批有效预留；负数先由原CHECK约束拒绝。审计表仅向店员/管理员授予查询权限，不向应用授予改写或删除历史的权限。

## 订单完成规则

`tr_OrderCompletion` 对订单插入、更新、删除作集合判断，拒绝直接插入完成订单，以及完成状态、完成时间、金额、优惠的重复改写或删除。只有从 `待出库` 转到 `已完成` 才能通过以下检查：

- 至少一条明细，商品存在、购买数量和成交价为正；订单总额等于明细总额，成功支付等于实付，优惠额与原价/成交价/折扣率相符。
- 每明细已转出库预留量和销售出库流水量都等于购买数量，没有遗留有效预留；按明细和批次核对出库数量一致。
- 出库批次属于所购商品、质量合格、完成当天未到期；余下现存量覆盖其他有效预留，并与该批全部库存流水净额相符。

任何一行不满足，THROW 51812使整个语句和失败事务拒绝，不能只让其中合法行完成。触发器负责拒绝非法状态，不自动扣货或赠分；[第10周完成过程](../../sql/week10/procedure.sql)在一个事务中先转预留、扣库存、写流水，再改状态并赠分，因此与触发器兼容。直接SQL的库存修改会被审计，但实际业务仍应使用过程维护库存流水；存在账面/流水差异时不能完成订单。

零影响行判断必须在设置NOCOUNT之前读取 `ROWCOUNT_BIG()`；集合实现遵循[Microsoft多行触发器说明](https://learn.microsoft.com/en-us/sql/relational-databases/triggers/create-dml-triggers-to-handle-multiple-rows-of-data?view=sql-server-ver16)。本实现检查状态转换时的数据，不试图通过触发器替代整个角色系统；共享顾客登录的本人权限仍在Web后端执行。

## 三类窗口查询

[window_query.sql](../../sql/week11/window_query.sql)顶部两个日期变量为含首尾日的完成日期范围，默认2026年9月；仅查询完成销售，不计待支付、待出库、取消订单。

| 查询 | 行粒度和窗口 | 业务含义 |
| --- | --- | --- |
| 商品销售额排名 | 第10周商品汇总上执行 `DENSE_RANK ORDER BY SalesAmount DESC` | 识别收入贡献较高的商品；相同金额同名次，下一名不跳号；商品编号只决定展示顺序 |
| 累计销售额 | 一行一完成订单；按 `CompletedAt,SalesOrderID` 排序，`ROWS UNBOUNDED PRECEDING` 到当前行 | 观察所选范围内收入如何逐单累积，同秒订单以唯一编号稳定排序 |
| 最近三笔均额 | 一行一完成订单；相同顺序，`ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` | 平滑逐笔订单金额波动；窗口是三笔订单，跨日期仍连续，首两行按实际1/2笔平均 |

排名之前的商品聚合是业务需要；累计和移动平均保留每张原始订单行。平均值按SQL decimal返回六位小数，不把缺少前驱的窗口补零。窗口只在选定日期范围内计算，不额外纳入开始日期之前的订单。窗口定义见[Microsoft OVER文档](https://learn.microsoft.com/en-us/sql/t-sql/queries/select-over-clause-transact-sql?view=sql-server-ver16)。

默认种子结果：商品S01为44.00元排名1，S02为16.50元排名2，S00为4.00元排名3；ST00/ST01累计48.00/64.50，移动平均48.00/32.25。测试另在事务内通过真实触发器完成4张模拟订单，形成6行结果，核对满3笔窗口、同时间戳排序；并以独立小表验证10/10/5金额对应名次1/1/2。模拟数据最终回滚，不改历史完成订单金额。

## 复现与交付

先完成第10周空库安装及测试，再在同一专用库执行：

```powershell
./scripts/Run-Week11.ps1 -Database $env:LAB_TEST_DATABASE
python tests/Test-Week11.py
```

本脚本不重新建库；仅安装可重复执行的触发器/审计表并展示三组查询。重复安装不会清空审计记录。当前Linux Web新部署入口先装第10周对象，再装本周触发器；已有库升级需审查目标和历史数据，不能把新应用直接接到旧模式。

[测试源码](../../tests/Test-Week11.py)涵盖单条/批量插入、修改、删除、无变化、有效预留边界、审计回滚、合法两单完成、批量一行非法、错误支付/商品/数量/批次/流水、重复完成、三类窗口及Web集成。[结果目录](../../result/week11/README.md)保存72项输入、预期、实际结果，库存审计、完成状态和窗口结果。使用第二个新库再次按周顺序复现，并在触发器开启下重跑原完整Web103项回归。
