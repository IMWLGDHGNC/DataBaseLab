**第一阶段 · 第1—4周**

## 数据库初建与CRUD

### 阶段作业：可运行的数据库原型（v0.1）

README：项目范围、业务角色、业务流程、脚本执行顺序与复现步骤。

sql目录：建库的SQL语句、构建样例数据的SQL语句、CRUD、构建查询/视图的SQL语句、约束与角色的SQL语句。之前每周任务中的要求也要包含。

结果目录：成功建库的截图，正常用例、非法数据、越权访问和关键查询结果截图。CRUD的结果截图，不同的统计视图与不同角色之间权限结果截图。之前每周任务中的要求也要包含。

阶段报告：应该包含设计思路，实验过程，实验总结。重点应该说明：

经营场景与业务流程，哪些信息进入数据库、哪些暂不进入，为什么

表是如何设计的，主码、候选码、外码如何设置及理由

完整性约束：角色与权限如何划分，给出正反例

ai_log：记录AI建议、人工修改及验证结论；

AI嵌入方式  可以用AI帮助确定小卖部/奶茶店的数据边界、角色、业务流程，但学生须进行判断与修改并能解释。自行完成数据库建立，并用反例、约束和执行结果证明正确性。

## 第四周任务  ch4 连接、视图、完整性、授权

### 1. 本周目标

### 完成多表查询、统计视图、主外键/检查约束和角色权限。

### 2. 任务

1. 完成多表查询：围绕订单、订单明细、商品、会员等表编写连接查询，能够回答完整的业务问题。

2. 完成统计查询：使用聚合函数、GROUP BY、HAVING 和必要的子查询，统计销量、销售额、库存或会员消费情况。

3. 创建统计视图：把后续会重复使用的统计查询封装为视图，并验证视图查询结果。例如：订单详情视图、商品销售统计视图和库存状态视图等。

4. 补充完整性约束：检查并完善主码、外码、UNIQUE、CHECK、DEFAULT 和是否允许空值等约束。

5. 划分角色权限：根据第一周的角色清单创建数据库角色，授予完成工作所需的最小权限，并测试越权操作。

6. 完成 v0.1 复现：从空数据库依次运行建库、样例数据、查询、视图、约束和权限脚本。

### 3. 本周作业

- query.sql：包含多表连接、聚合、子查询等有明确业务含义的查询。

- view.sql：创建并查询不同的统计视图。

- constraint.sql：创建约束，并包含合法数据成功、非法数据失败的验证用例。

- role.sql：创建角色、授予权限，并展示正常操作与越权失败。

- v0.1 阶段验收清单：README（项目范围、角色、流程、脚本顺序与复现步骤）、sql 目录（建库、样例数据、CRUD、查询/视图、约束与角色）、result 目录（成功建库、正常、非法、越权及关键查询结果）、阶段报告、ai_log 和组内分工全部齐全；从空库按 README 执行能够复现。

### 4. 提示与常见问题

- INNER JOIN 和 LEFT JOIN 的结果不同，选择连接方式时要结合业务问题解释。

- 完整性约束要在数据库中真正生效，不能只在报告中写一条业务规则。

- 角色权限遵循最小权限原则，不要为了方便直接授予数据库所有权限。

- 截图只能作为证据，提交内容仍要包含可以重新执行的 SQL 脚本。

- AI 生成的查询可能语法正确但业务含义错误，必须用样例数据和预期结果核对。
