第十周任务  存储过程与函数

1. 本周目标

在 v1.0 数据库的基础上，将补货选择、订单完成、库存调整和折扣等业务写成可重复调用的存储过程和函数。所有对象都要带参数，完成输入检查和错误处理，并用正常和异常数据进行验证。

2. 任务

1. 编写销售统计存储过程：输入开始日期和结束日期，统计订单数量、销售数量、销售金额以及商品销售情况。检查日期范围，正确处理没有销售记录的情况。

2. 编写库存调整存储过程：输入商品编号、调整数量、调整原因和操作员工编号。商品不存在、调整数量为零或库存不足时，应拒绝操作；调整成功后保存新的库存数量和调整记录。

3. 编写补货量函数：根据当前库存、最低库存量或目标库存量计算补货数量。库存已经达到目标时返回 0，商品不存在时进行明确处理，返回值不能为负数。

4. 编写销售汇总表值函数：输入日期范围，返回商品编号、商品名称、销售数量、销售金额和订单数量等汇总结果，并能够在 SELECT 语句中调用。

5. 完成折扣计算业务：根据会员身份、订单金额或商品分类计算折扣率和折扣金额。折扣计算应使用函数，历史订单中的实际折扣和成交价应保存到订单或订单明细中。

6. 整合任务：将以上过程与函数整合进之前完成的v1.0 数据库，以上业务在数据库中实现，如果之前的应用程序中已经实现，将原先的实现替换。在 SQL Server 中完成，只在页面层中调用

3. 本周作业

procedure.sql：存储过程代码。

function.sql：函数代码。

调用与测试脚本：测试补货、订单完成、库存调整和折扣业务的正常输入、空值、错误编号、错误日期、非法数量、非法折扣和重复调用。

区分存储过程与函数

结果记录：保存输入参数、预期结果、实际结果、成功结果、错误提示以及未写入不完整数据的验证结果。

4. 提示与常见问题

存储过程适合完成选择补货、订单完成和库存调整等会改变数据的业务；函数适合完成补货量、折扣和销售汇总等计算或查询。

日期统计要说明开始日期和结束日期是否包含当天；不要把商品编号和日期直接写死在过程或函数中。

过程和函数的参数、表名和字段名应与数据库设计保持一致；测试时同时准备正确数据和错误数据，并保存错误处理结果。
