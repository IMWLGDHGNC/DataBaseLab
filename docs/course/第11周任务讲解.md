第十一周任务  触发器与窗口函数

1. 本周目标

使用触发器自动记录库存变化并检查订单完成条件，使用窗口函数完成排名、累计值和移动平均查询。重点理解触发器的自动执行方式，以及窗口函数在保留明细行的同时完成统计的方法。

2. 任务

1. 编写库存审计触发器：库存增加、减少或修改时，自动记录商品编号、调整前数量、调整后数量、变化数量、操作时间、操作类型和操作人员。

2. 编写订单完成规则触发器：订单状态改为已完成时，检查订单明细、商品、购买数量、库存和订单金额。条件不满足时拒绝修改，已经完成的订单不能重复完成。

3. 完成排名查询：使用 RANK、DENSE_RANK 或 ROW_NUMBER，按照销售数量、销售金额或订单数量对商品进行排名，并说明排名结果的业务含义。

4. 完成累计值查询：按照订单日期或商品顺序，统计累计销售金额或累计销售数量，并明确查询的排序字段。

5. 完成移动平均查询：计算最近 3 天、最近 3 笔订单或最近 3 个月的平均销售量或销售金额，并说明窗口范围和业务用途。

3. 本周作业

trigger.sql：提交库存审计触发器和订单完成规则触发器。

window_query.sql：提交一条排名查询、一条累计值查询和一条移动平均查询。

测试脚本：测试单条插入、单条修改、多条修改、正常操作、非法数据和触发器拒绝操作。

结果记录：保存审计记录、订单状态、排名、累计值和移动平均的查询结果，并说明结果是否符合业务预期。

4. 提示与常见问题

SQL Server 触发器一次可能处理多行数据，不能只用一个变量保存一行数据，应结合 inserted 和 deleted 进行判断。

触发器应同时考虑插入、修改和删除，且不宜加入过多复杂业务，以免影响普通增删改操作。

窗口函数不会减少原始数据行数，而是在每一行旁边增加统计结果。累计值要设置明确的排序方式，移动平均要说明窗口大小。
