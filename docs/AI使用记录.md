### 部署与验证

- 使用用户私下提供、未写入仓库的 SSH 地址和账户登录课程服务器；服务器端 SSH 偶尔因 `Exceeded MaxStartups` 在认证前断开，降低频率重试后连接成功。

- 创建容器 `database-lab-sqlserver`、持久化卷 `database-lab-sql-data` 和 `unless-stopped` 重启策略。SQL Server 端口只绑定服务器本机 `127.0.0.1:1433`，组员通过 SSH 隧道访问，不直接暴露数据库端口。
- SQL 管理密码随机生成，只保存在服务器用户目录的权限 `600` 文件中，没有写入仓库或本记录。
- Linux 容器不能直接使用面向 Windows LocalDB 路径的建库脚本；远端使用普通 `CREATE DATABASE` 建空库，再执行其余仓库 SQL。首次执行发现容器内文件权限问题和 `QUOTED_IDENTIFIER` 默认值差异，分别修正只读权限并使用 `sqlcmd -I -f 65001` 后重新从空库执行。
- 最终得到 SQL Server 2022 CU27 `16.0.4295.3`、15 张业务表和 46 行样例数据；`VERIFY_PASS`、`CRUD_PASS`、12 项 `CONSTRAINT_TESTS_PASS` 全部通过。重启容器并等待业务库恢复后，再次得到 `VERIFY_PASS`，确认 Docker 卷持久化有效。
- 新增[服务器 SQL Server 环境](服务器SQL环境.md)，记录连接、密码存放位置、状态检查、验证、重新导入差异和已知限制；README、本地环境与 Week3 文档加入入口。

### 边界

- 本次部署没有配置定时 `.bak` 或异机备份；Docker 卷持久化不能替代备份。
- 当前保留 `sa` 供课程实验使用。若后续接入应用，应创建最小权限账号并补充备份、恢复和权限管理方案。
