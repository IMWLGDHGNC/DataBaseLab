# Week7：数据库 Web 应用设计与实施说明

第 7–9 周课程讲解把三周合为一个应用开发任务。我们先把第六周的 v1.0 模式作为应用基线，建立页面、业务、数据访问和 SQL Server 四层，再打通登录、商品、库存、订单及订单明细的基础流程，并完成角色页面、事务与集成验证。课程原文保存在小组私下材料中，公开仓库记录实现和可复现的技术说明。

## 1. 输入与范围

- 数据库输入是第六周迁移后的 **v1.0 独立样例库**，含 15 张业务表、46 行初始样例。应用部署不修改 `DataBaseLab_Week4` 正式演示库；先运行第六周完整脚本并通过 `W6_REGRESSION_PASS`。
- Web 端使用 Flask。页面层只做交互和基本格式校验；服务层掌握角色与业务规则；DAO 层独占参数化 SQL、连接和事务；SQL Server 继续负责主外键、CHECK、UNIQUE 与数据持久化。
- 经营范围沿用 [Week1](Week1.md)：单店、单仓、模拟支付。销售下单时**锁定可售库存而不立即减少 `OnHandQty`**；付款后仍待出库，员工确认出库才减少现存量并写流水。这是现有订单、锁定与库存模型的语义，不能为满足界面示例而改变。
- 顾客、店员和管理员是应用角色；经营岗位及 SQL Server 数据库角色另有定义。界面可隐藏按钮，但每条写请求仍由服务端鉴权。DAO 按应用角色使用受限 SQL 登录和表级授权；顾客的“仅本人”行级范围由服务层再次限制。不把 `sa` 或密码放入代码、页面、仓库和日志。

## 2. 四层与数据流

```text
浏览器页面 / JSON API
        ↓ 参数解析、会话与展示
Flask 路由
        ↓ 角色检查、业务验证、操作编排
Service
        ↓ 参数化 SQL、单连接事务、回滚与释放
DAO
        ↓ 受限 SQL 登录、表级授权、表约束
SQL Server v1.0
```

读例：商品页请求 `GET /api/products`，路由解析筛选条件，服务层限定可见商品，DAO 用参数绑定读取商品和可售数量，响应统一 JSON 结构并展示。

写例：顾客提交订单时，路由只接收商品、数量和收货快照；服务层从登录会话确定顾客身份，检查商品在售、数量和收货信息；DAO 在一次事务中锁定可售批次，写订单、明细和预留记录，任一步失败全部回滚；页面只收到订单号或统一错误码。模拟支付、确认出库与赠分分别由后续受控事务执行。

## 3. 功能与权限

| 操作 | 顾客 | 店员 | 管理员 |
| --- | --- | --- | --- |
| 登录、退出、查询在售商品 | 是 | 是 | 是 |
| 查询本人订单、创建订单、删除待支付订单中的明细或取消订单 | 是，仅本人 | 否 | 是，管理视角 |
| 查询批次库存与有效锁定 | 否 | 是 | 是 |
| 盘点调整、确认出库 | 否 | 是 | 是 |
| 新增、修改、停用商品 | 否 | 否 | 是 |
| 查询所有订单和明细 | 否 | 是 | 是 |

“删除”优先遵守历史业务事实：已支付、已出库的订单与明细不物理删除；未支付订单允许取消并释放预留，只有尚未形成不可撤销后续记录的草稿明细可删除。已产生库存、支付或积分流水的实体保留历史并用状态表达停用或取消。

## 4. 事务与并发边界

1. **下单：** 对批次和有效预留采用锁定读取；先确认商品状态、保质期、批次质量与可售量，再插入 `SalesOrder`、`SalesOrderItem`、`InventoryReservation`。金额由数据库当前售价计算并作为历史成交价快照，不接受前端提交的价格。多商品任一项不足时整体回滚。
2. **模拟支付：** 只允许本人待支付订单、金额一致且尚无成功支付；写 `PaymentRecord` 并转为待出库。重复请求不得产生第二笔成功支付。
3. **出库：** 只允许待出库且已成功支付的订单；检查有效预留、批次质量和到期日，再扣减 `InventoryBatch.OnHandQty`，写 `InventoryMovement`，转移锁定状态并完成订单；会员积分及余额在同一事务更新。任一步失败全部回滚。
4. **库存调整：** 受限于店员或管理员，写批次余额与调整流水于同一事务；调整后现存量不得为负，也不得小于有效预留量。
5. **商品维护：** 管理员可新增商品、修改当前价格或状态；有历史引用的商品通过停售保留。候选码与外键约束仍由数据库执行。

请求必须使用参数绑定，动态 SQL 不拼接用户输入。ID 生成、金额计算、锁定、写入与提交/回滚均在服务端完成。数据库事务失败时返回稳定错误码，不向浏览器回显 SQL 或堆栈。

## 5. 登录、异常与日志

演示账号由初始化命令生成，密码保存为带盐哈希。会话保存最小身份信息，写请求检查会话和角色；顾客身份与数据库 `CustomerID` 在服务器端固定绑定，不接受页面指定他人编号。表单执行必填、类型、长度和正数校验；DAO 和数据库仍执行最终检查。

API 成功统一返回 `{"ok":true,"data":...,"request_id":...}`，失败返回 `{"ok":false,"error":{"code":...,"message":...},"request_id":...}`。分类覆盖输入错误、未登录、无权限、对象不存在、业务冲突、约束冲突、数据库暂不可用和事务失败。后端日志记录时间、请求标识、操作、角色、错误码和结果；不记录密码、连接串、收货联系方式、原始 SQL 参数或内部异常到前端。
