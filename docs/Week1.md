# Week1 - 线上零食网店数据库任务构建

## 经营场景——线上零食店

本项目以线上零食店为经营场景，覆盖**采购、库存和销售**三个主要流程，并包含会员积分与商品保质期管理。后续可以在现有数据基础上扩展销量分析、库存预警和预测驱动补货等功能，适合作为贯穿本学期的数据库项目。

第一阶段聚焦商品、采购、库存、销售和会员管理的最小完整闭环，暂不实现复杂物流、推荐系统和退货流程，避免项目范围过度扩大。

## 经营参与者及职责

### 内部员工

1. **店长：** 负责商品定价、员工管理、查看营收与库存数据，并审批采购。
2. **采购员：** 负责管理供应商、创建采购订单并跟踪到货情况。
3. **库存管理员：** 负责采购验收、商品入库、销售出库、库存盘点和临期商品检查。
4. **订单管理员：** 负责处理顾客订单、确认出库、取消异常订单并处理售后。

### 外部参与者

1. **普通顾客：** 浏览商品、提交订单、完成支付并申请基本售后服务。
2. **会员：** 具备普通顾客的功能，同时可以累计或使用积分并享受会员优惠。
3. **供应商：** 接收采购订单，向零食店供货并提供相应的商品批次信息。

## 核心数据对象

1. **商品和商品类别：** 保存商品名称、品牌、规格、类别和建议售价等基础信息。
2. **供应商：** 保存供货方的基本资料及合作状态。
3. **员工和员工角色：** 保存员工资料和岗位，为后续权限设计提供依据。
4. **采购订单和采购订单明细：** 分别记录一次采购及其中每种商品的数量和成交单价。
5. **库存批次和库存变动：** 记录每批商品的生产日期、到期日期、现存数量以及入库、出库等变化。
6. **顾客和会员：** 保存顾客基本资料、会员状态和当前积分等信息。
7. **销售订单和销售订单明细：** 分别记录一次销售交易及其中每种商品的数量和实际成交单价。
8. **支付记录：** 保存支付金额、支付状态和第三方交易编号，不保存完整银行卡信息。
9. **积分变动记录：** 保存积分增加、使用和撤销的原因与时间，便于追溯。

## 业务流程

### 采购与入库

库存不足或低于预警值 → 采购员创建采购订单 → 店长审批 → 供应商发货 → 库存管理员验收商品和批次信息 → 商品入库 → 库存增加 → 采购订单完成。

### 销售与出库

顾客浏览商品并下单 → 系统创建销售订单和订单明细 → 检查并锁定库存 → 顾客支付 → 支付成功 → 库存管理员或系统确认出库 → 扣减库存 → 订单完成。

### 会员积分

会员订单完成 → 系统按照实际支付金额计算积分 → 写入积分变动记录 → 更新会员积分余额。

### 异常处理

库存不足或支付失败 → 订单取消 → 释放已经锁定的库存；订单完成前由顾客主动取消时，也需要释放库存。退货流程暂不进入第一阶段范围。

## 数据边界

### 进入数据库的数据

| 数据 | 进入数据库的理由 |
| --- | --- |
| 商品、类别和价格 | 支持商品展示、销售和分类统计 |
| 供应商资料 | 支持采购管理和供货来源追溯 |
| 员工及其角色 | 支持职责划分和后续数据库权限控制 |
| 采购订单及明细 | 记录采购数量、成本和到货状态 |
| 销售订单及明细 | 记录交易内容、成交价格和订单状态 |
| 库存批次及库存变动 | 追踪商品数量、生产日期、到期日期和出入库情况 |
| 顾客、会员及积分变动 | 支持会员识别、积分计算和积分追溯 |
| 支付结果 | 判断订单是否可以完成，但只保存必要的支付结果和交易编号 |

### 暂不进入数据库的数据或功能

| 数据或功能 | 暂不进入的理由 |
| --- | --- |
| 完整银行卡和支付密码 | 属于敏感信息，应交由第三方支付平台处理 |
| 供应商物流实时轨迹 | 当前只关心是否到货和验收结果，不需要记录实时位置 |
| 商品图片文件 | 数据库只保存图片地址，图片文件由文件系统或对象存储管理 |
| 顾客聊天记录和广告点击数据 | 不属于当前采购、库存和销售的核心闭环 |
| 推荐系统 | 第一阶段不涉及个性化推荐，后续有需要时再扩展 |
| 退货流程 | 涉及退款、逆向库存和积分撤销，第一阶段暂不实现 |

## 初步业务规则

1. 一个销售订单至少包含一条订单明细。
2. 商品成交单价记录在订单明细中，避免商品售价调整影响历史订单。
3. 库存数量不能为负数，只有库存充足时才能锁定和出库。
4. 商品批次的到期日期必须晚于生产日期，出库时优先选择较早到期的批次。
5. 只有已经完成的会员订单才能增加积分；订单取消时不能增加积分。
6. 每次库存增加或减少都必须有对应的采购、销售或盘点原因，以便追溯。
