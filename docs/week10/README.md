## 对象与调用

| 对象 | 参数与返回 | 职责 |
| --- | --- | --- |
| `sp_SalesStatistics` | 开始/结束日期；总计和逐商品两个结果集 | 统计完成订单数、销售件数、成交金额；无销售返回零总计和空商品集 |
| `sp_AdjustInventory` | 商品、非零有符号数量、原因、员工、可选批次；前后库存 | 原子调整批次并写盘点流水；拒绝低于有效预留或整数上限 |
| `fn_ReplenishmentQty` | 商品、可空目标；非负 bigint 或 NULL | 目标减可售库存；默认目标为商品 ReorderLevel；达到目标返回0 |
| `fn_SalesSummary` | 开始/结束日期；商品、名称、数量、金额、订单数 | 可在 SELECT 中使用的内联表值函数 |
| `fn_DiscountRate` / `fn_DiscountAmount` | 顾客 / 金额与折扣率 | 正常会员5%优惠，非会员0；非法输入返回NULL |
| `sp_PriceOrder` | 订单、是否初始化；实付、折扣率、优惠额 | 待支付订单初始化或重算，保存历史原价、成交价和优惠快照 |
| `sp_SelectReplenishment` | 商品、可空目标；建议数量 | 将补货函数的未知商品/非法目标转换为明确异常；不自动创建采购 |
| `sp_CompleteOrder` | 已支付订单、在职员工 | 检查付款/金额/批次/预留，扣库存、转预留、写出库流水、完成订单并赠分 |

过程用于业务操作和明确报错；函数用于只读查询与可组合计算。UDF 不执行数据修改，不能用 THROW，因此标量函数以 NULL 明确表示非法输入，表值函数的非法日期范围返回空表；面向应用的入口先检查参数并给出错误。参数与查询示例见 [call_examples.sql](../../sql/week10/call_examples.sql)，完整正反例见[测试](../../tests/Test-Week10.py)。

## 业务口径

- 销售只统计 `已完成`，以 `CompletedAt` 作为销售发生时间。开始日和结束日均包含整天，日期相同可查当天，最大 DATE 值不会因加一天溢出。商品订单数不能直接相加当作整单数，同单可含多商品。
- 可售库存只包含未到期且合格的批次，扣除有效预留；隔离和过期库存不作为可用补货基数。商品不存在、目标负数返回 NULL；NULL 目标使用阈值。补货建议只辅助采购选择，验收入库保留已有采购来源与批次流程。
- 每单在创建时保存会员折扣率，后续编辑沿用该快照，不因会员状态变化或商品改价而改变既有明细原价。`DealUnitPrice = ListUnitPrice - ROUND(ListUnitPrice × DiscountRate, 2)`，优惠额为原价总额减成交总额。先按单价舍入，再乘数量；2件4.40元商品为8.36元，改3件为12.54元。
- 新增订单明细保存 `ListUnitPrice`；迁移将历史原价设为原成交价，历史折扣为0，不重算旧订单。兼容旧SQL调用者的原价NULL仅表示尚未提供原价快照，计价过程会从其成交价补齐；Web始终显式提供原价。已支付/完成订单不允许计价过程重算。
- 调整必须定位既有批次；同商品仅一个批次时可省略批次编号，多批次时必须指定，不能凭空建立缺少采购来源的库存。单次调整范围为±100000，0、空原因、不在职员工、商品/批次不匹配均拒绝。
- 完成订单要求成功支付金额等于明细金额、每明细有效预留恰好等于购买数量、商品和批次一致、库存覆盖该批全部有效预留、批次合格且未到期。按批次汇总扣减；会员按实付金额向下取整赠分，非会员不赠分。重复完成拒绝，不能重复扣货或赠分。

## 事务、权限与应用

写过程与 v1.0 Web 使用同一个事务级应用锁 `DataBaseLab.WebWrite`，防止跨入口的检查和写入交错。过程独立调用时自建并提交事务；外层已有事务时使用保存点，不提交外层事务。异常若已使事务不可提交，整体回滚；其他异常回滚本过程保存点。调用者收到失败必须结束/回滚该请求，不能继续使用失效事务。库存操作暂存并恢复 SESSION_CONTEXT 操作员工，供下一周审计使用。

页面 → Flask角色/格式校验 → DAO参数绑定 → SQL过程/函数。`service.py` 的盘点与完成规则已移入SQL，不保留Python的第二套扣货、赠分实现；创建及增改删明细统一调用计价过程。补货建议和销售汇总可在库存页面查询，详情展示实际优惠。SQL错误51801/51802/51803/51804分别映射为输入错误/不存在/无权限/业务冲突，不向页面返回SQL堆栈。

先应用第7周受限角色授权，再运行[本周权限](../../sql/week10/permissions.sql)，撤回店员/管理员直接改现存量、订单完成状态、积分余额和积分插入的权限，授予对应过程执行权限。采购验收仍需原有批次/入库流水写权限。应用共享顾客数据库登录的“仅本人”边界继续在后端校验，过程参数不是独立的顾客身份认证。

## 复现

Windows需要已初始化的SQL Server 2022 LocalDB、Python3.12，以及 Flask、pymssql、pyodbc。安装依赖可使用自己的虚拟环境，不提交环境或凭据。从根目录执行：

```powershell
./scripts/Run-Week10.ps1 -Database DataBaseLab_Week6_Week102026111101
$env:LAB_TEST_DATABASE = 'DataBaseLab_Week6_Week102026111101'
python tests/Test-Week10.py
```

数据库名必须使用尚未存在的新名称，重复建库会明确拒绝。执行器从第3–6周空库迁移开始，再运行本周 `migration → function → procedure → permissions`；第10周迁移只运行一次，过程、函数、授权可重复安装。Python测试只允许专用命名的样例库，所有模拟身份和原始异常保存在忽略目录。

Linux新建Web样例库继续使用[部署脚本](../../scripts/Run-Week7-Server.sh)，第7周授权后安装本周SQL。已有v1.0应用升级须先备份并审查目标库，在停写时按上述SQL顺序升级，再部署新应用；本次没有对既有远端环境执行升级。
