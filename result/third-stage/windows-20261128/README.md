## 三会话观察

RCSI 关闭时 A/B/观察连接分别为 53/105/103，开启时为 104/105/53。按 A/B 脚本步骤重放，每轮核对两端 `@@TRANCOUNT=0`、`XACT_STATE()=0`。下表对应[实测轨迹](evidence.json)的 `concurrency` 字段。

| 场景 | 本轮观测 |
| --- | --- |
| 同库存写等待 | A 持 P 的 KEY X，B 请求 X。A 提交时 P=13、订单完成；A 回滚时 P=15、订单待完成。两轮补货都提交 |
| 脏读与已提交读 | 未提交读看见 15，A 回滚后为 10。RCSI 关闭时已提交读等待并返回 10；开启时普通读先返回 10，带 `READCOMMITTEDLOCK` 仍等待 |
| 不可重复读与可重复读 | 已提交读在同一事务中读到 10、15。可重复读保持 P 的 S 锁，两次读 10，B 等待 A 提交 |
| 死锁与同序访问 | A 持 P 等 Q，B 持 Q 再请求 P，B 返回 1205。受害者回滚后 P/Q 为 8/6。两个会话按 P→Q 访问后仅普通等待，P/Q 为 13/11 |
| 真实订单和补货 | B 等待 `DataBaseLab.WebWrite` 的 APPLICATION X 锁。A 提交／回滚后 P 分别为 13／15，采购单均已收货 |
| 两单竞争 | 两张订单各需 6 件，A 提交后 P 剩 4，B 返回 51804。仅 A 留有出库流水、库存审计及 30 积分 |
