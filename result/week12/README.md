2026-11-18 在 SQL Server 2022 LocalDB 的独立样例库实测。[逐项结果](checks.json)记录初始数据、操作、预期和实际结果。[复现摘要](reproduction.txt)记录安装和回归通过标记。材料中的业务数据均为模拟数据。

| 操作 | 初始数据 | 预期与实测 |

| 订单提交 | P/Q 现存 20/15，预留 3/4，已支付 27.00 元 | 新连接读到 P/Q 现存 17/11，订单已完成，两笔预留转出库，出库流水和审计各两行，赠分 27。支付和明细保持原值 |
| 订单中途回滚 | 同订单提交初始数据 | 测试触发器在扣货、审计、流水、状态均已写入时抛出 51920。回滚后数量恢复 20/15，订单保持待出库，预留有效，流水、审计、积分均无新增 |

所有失败用例在清理后均为 `@@TRANCOUNT=0`、`XACT_STATE()=0`，整个 `dbo` 的逐表数据摘要与用例准备前一致。测试比较的是行内容，审计表自增编号允许因失败出现空洞。单独验证了采购入库由外层事务控制提交、会话操作人复原。测试使用第十二周之前已存在的分类、商品、采购、销售、支付、库存及积分关系。

另在独立样例库复跑第10周 87 项、第11周 72 项及 103 项 Web 回归。权限复核确认店员和管理员可执行入库过程，顾客无执行权，三个角色均无直接插入批次、流水或更新收货时间的权限。在已有专项结果的样例库重装第12周对象后，各表数据摘要与重装前一致。

Web 测试连接使用 Windows LocalDB ODBC 适配，执行真实 Flask 路由、服务和 DAO SQL。课程服务器未部署，人工审核待确认。复现需要 SQL Server 2022 LocalDB、Python 和 `pyodbc`。Web 回归另需 [应用依赖](../../app/requirements.txt)。运行入口见[第12周说明](../../docs/week12/README.md)。
